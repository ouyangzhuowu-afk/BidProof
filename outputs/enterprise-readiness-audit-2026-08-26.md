# BidProof 企业就绪度审计

日期：2026-08-26

## 结论

当前不是“只差真实企业任务”。更准确的判断是：工程 MVP 已形成可试运行产品，真实企业任务是业务验收的首要阻塞；同时，若目标是企业生产部署，还存在数据持久化、身份治理、通知集成和运营保障等生产化缺口。当前不能把“85 passed”、OCR 78/78 页提取成功或 31 条独立复核候选，表述为泛化准确率或成熟企业产品证明。

置信度：高。依据是项目状态台账、接口/前端契约和本轮全量回归；对真实业务价值和跨行业准确率的判断置信度为低，因真实任务台账仍为 0。

## 已具备并可试运行

| 能力 | 当前证据 | 边界 |
| --- | --- | --- |
| 多格式上传与定位 | PDF/DOCX/XLSX/PPTX/TXT/MD 抽取；非 PDF 使用段落、单元格、文本块或行号定位 | 旧版 DOC/XLS/PPT 需转换；扫描件依赖 OCR |
| 任务批量管理 | 批量归档、恢复、删除、项目筛选、导出 HTML/PDF/CSV | 尚无真实企业操作时长和误操作反馈 |
| 证据链与解释 | 要求、来源引用、企业证据、风险影响、建议动作、人工决策 | 规则命中是启发式候选，不自动等于通过 |
| 协作与治理 | 成员角色、评论、可关联要求项的整改行动、截止日期、审计导出、用量与隐私说明 | 仍是本地 SQLite / 本机文件存储 |
| 运维闭环 | 作业进度、失败重试、健康检查、备份与恢复校验 | 公网试点依赖本机进程，不是高可用生产部署 |

## 真实企业用户还会需要

### 试运行前的高优先级

1. **真实任务台账与复核工作流**：记录每个任务的原始文件、人工确认、漏报/误报、耗时、最终投标结果和付款意愿。没有这条，无法判断精度是否足够，也无法知道产品是否真的节省时间。
2. **大文件与长任务体验**：上传进度、可取消扫描、断点续传、明确的 OCR/抽取阶段、失败原因和重试入口。当前有后台作业和重试，但还需真实大文件压力验证。
3. **批量操作保护**：筛选结果预览、删除二次确认、撤销窗口、导出范围提示。现有删除/归档能力应在真实用户操作中验证是否足够防误操作。
4. **结论落地**：整改项应能关联要求项、负责人和截止日期，并在即将到期/逾期时提醒。当前已实现关联、状态跟踪和逾期提示，但尚无通知渠道。

### 生产部署前的硬缺口

1. **持久化与灾备**：对象存储、数据库迁移/备份策略、恢复演练、加密和密钥轮换；单机 SQLite 与本地上传目录不满足企业连续性要求。
2. **企业身份治理**：密码找回、MFA/SSO、会话撤销、成员批量导入、最小权限矩阵和离职回收。当前角色模型足够做试点，不足以宣称企业身份合规。
3. **通知与集成**：邮件/企业微信/飞书提醒、Webhook、API 密钥和幂等重试，便于接入现有投标流程。
4. **可观测性与支持**：结构化日志、指标、告警、租户级配额、限流、错误追踪和客户支持诊断包。
5. **数据合规控制**：上传文件病毒扫描、敏感信息识别/脱敏、导出水印、访问日志保留期限和租户数据删除证明。

### 当前不应优先扩张

自动生成/提交标书、自动报价、自动法律结论、跨行业规则大而全、复杂检索增强。这些会扩大风险面；应先完成真实任务和准确度证据，再根据付费信号决定。

## 精度判断

- 当前能证明的是：定位契约、缺证据降级、人工复核和 OCR 失败页处理符合工程规则；匹配输出为未校准计数，不伪装成概率。
- 当前不能证明的是：对不同企业、行业、文档版式的召回率、严重风险漏报率、端到端节省时间和付款意愿。
- 31 条独立复核结果属于单一材料集的确认，不是总体准确率；78/78 页 OCR 提取成功也不等于语义识别正确。
- 在真实任务台账未达到预设样本前，产品结论应标记为“可试运行 / 准确率待验证”，而不是“成熟企业产品”。
