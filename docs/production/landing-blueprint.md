# Landing Page 蓝图

2026-09-23。初稿在代码实现前确认；本版同步最终页面文案与组件结构。

核心用户为IT服务/软件实施企业的售前、商务和项目负责人。将临近截标的焦虑转为可逐项处理的核验流程。品牌采用深松绿、暖白、克制的风险红和充足留白；页面主视觉用真实可操作的代码组件。

| 组件 | 内容 / 行为 |
| --- | --- |
| Header | 核心能力、交互演示、使用方案、常见问题；实际 /app 入口 |
| Hero | **截标之前，把每一条风险核对清楚。** 副标：从招标红线到企业资质，让每个判断回到原文页码。先处理可能一票否决的条款，再有序完成团队复核。主CTA进入审查工作台，次CTA查看交互演示；小字“个人工作区 · 团队协作”。 |
| Interactive Demo | 三种合成场景：必备声明缺失、资质有效期待核对、双引用可核销；两列摘录、页码、备注和核销状态，重置示例。无账号，在页面内运行，不上传文件、不写工作区。缺证据的场景不允许通过。 |
| Four Features | 风险优先、双向原文、连续核销、团队留痕 |
| Workflow | 上传 → 定位 → 核验 → 记录决定 |
| Trust | 展示可检验机制：页码引用、人工最终决定、空间与角色权限。客户评语、效率和认证无证据时不展示；简短保留“当前为试点阶段”，说明将通过真实任务评估漏报、误报、页码覆盖与处理耗时。 |
| Pricing | 个人工作区 / 团队协作 / 企业部署；分别按需求、团队需求、部署范围报价。引导按团队规模与部署范围选择；统一备注“当前为试点方案，价格与服务范围按需确认。”不虚构席位、SLA或免费政策，主入口仍通往实际工作台。 |
| FAQ | 漏报边界、扫描PDF/OCR、文件存放、团队协作、最终决策、费用与开放方式 |
| Final CTA | 下一份标书，带着证据做决定。工作台与演示双入口；移动端CTA不能遮挡正文或操作。 |

交互使用原生按钮/表单/折叠组件，支持键盘焦点和减少动态效果。无JS时主要文案、导航、CTA和FAQ仍可用。动态内容使用安全DOM API，不插入未经转义的富文本。SEO包含title、description、canonical、OpenGraph和Twitter；公开URL从部署配置安全注入，不把私有部署导向虚构域名。

性能目标为移动/桌面各自75分位 LCP≤2.5s、INP≤200ms、CLS≤0.1；本地测量仅是工程证据，不等同于真实用户达标。参照[Web Vitals官方定义](https://web.dev/articles/vitals)。Tailwind采用[官方Vite集成](https://tailwindcss.com/docs/installation/using-vite)，只在构建期运行。
